## REQ-23 — No administrator, mutable configuration or upgrade

> "No administrator, mutable configuration or upgrade."
> — DESIGN.md line 2, sentence 9

Test supplied with the requirement (workflow operationalization, not DESIGN.md text): "No account (deployer,
sponsor, treasury or other) has privileged control over the factory or raffles: no owner/role, pause, cancel,
rescue, parameter setter or forced withdrawal."

**Verdict:** contradicted · confidence: high

---

**What this demands of an implementation:** across `RaffleFactory`, every `Raffle` clone, and every base they
inherit, (a) no entry point reserved to a particular account may pause, cancel, rescue, reconfigure,
force-withdraw or upgrade; (b) no configuration value is written after construction / one-time initialization;
(c) the code a raffle or the factory executes cannot change. The named accounts are the deployer, the sponsor
(the `createRaffle` caller, `RaffleFactory.sol:L112` `sponsor: msg.sender`), the treasury (`protocolTreasury`),
and anyone else. Two kinds of caller check are not administrator power, because DESIGN.md asks for them: the
bearer check ("redemption requires current ticket owner") and the trusted-dependency callback ("Quote token and
Chainlink wrapper are trusted canonical dependencies").

---

**Where enforcement lives:**

This requirement is a prohibition, so it is enforced by structure: immutables, constants, a one-shot initializer,
fixed-target proxy bytecode, and no privileged entry points. That structure holds everywhere except one explicit
grant:

```solidity
// Raffle.sol:L276-L301
function enableRefunds() external override nonReentrant {
    uint256 deadline;

    if (status == Status.Active) {
        if (totalEntries == 0) {
            deadline = endTime;
            if (msg.sender != sponsor && block.timestamp < deadline) {
                revert RefundsNotAvailable(deadline, block.timestamp);
            }
        } else {
            deadline = drawRequestDeadline();
            if (block.timestamp < deadline) revert RefundsNotAvailable(deadline, block.timestamp);
        }
    } else if (status == Status.Drawing) {
        deadline = callbackDeadline();
        if (block.timestamp < deadline) revert RefundsNotAvailable(deadline, block.timestamp);
    } else {
        revert InvalidStatus(status);
    }

    uint256 liability = unsettledPot;
    unsettledPot = 0;
    remainingRefundLiability = liability;
    status = Status.Refunding;
    emit RefundsEnabled(msg.sender, liability);
}
```
- L282 exempts `msg.sender == sponsor` from the `block.timestamp < endTime` gate. While `status == Active` and
  `totalEntries == 0`, the sponsor alone can end the sale before `endTime`. Every other caller reverts until
  `endTime`.
- Every raffle is in that state as soon as `createRaffle` returns. Status becomes `Active` at `Raffle.sol:L428`
  inside the escrow transfer at `RaffleFactory.sol:L128`, and `totalEntries` stays 0 until the first
  `buyEntries` (`Raffle.sol:L230`). So the power exists on every raffle from creation until its first sale.
- L299 sets `Refunding`, which is terminal. There are six status writers: L165, L205, L252, L299, L428 and L521.
  L165 is the constructor and never runs on a clone. Each of the others requires a status other than
  `Refunding`, or `!initialized`:
  - `initialize` requires `!initialized` (L177).
  - `requestDraw` requires `Active` (L241).
  - `enableRefunds` reverts for `Refunding` (L292-L293).
  - `onERC721Received` requires `AwaitingPrize` (L422).
  - `fulfillRandomWords` requires `Drawing` (L511).
- In `Refunding`, anyone can call `releaseSponsorPrize` (`Raffle.sol:L395-L407`; status accepted at L397). It
  sends the escrowed prize to `sponsorRecipient` (L402-L404). Ending the raffle early at the sponsor's sole
  discretion, then returning the prize, is a cancel.
- Consequence, as far as the code shows: with `totalEntries == 0` there are no buyer funds. `unsettledPot` grows
  only at L233, in the same function that raises `totalEntries` at L230. If a buyer's first `buyEntries` lands
  after the cancel, it reverts at L215 (`_requireStatus(Status.Active)`, L573-L575), before USDC is pulled at
  L224. Once one entry is sold, L285-L288 applies the same deadline to every caller and the sponsor's privilege
  is gone.
- NatSpec says this is intended:
  - `IRaffle.sol:L37` "@param sponsor Prize depositor and empty-raffle cancellation authority."
  - `IRaffle.sol:L322-L323` "Also closes an empty raffle immediately for the sponsor and after sale end for anyone."
  - `IRaffle.sol:L410` and `IRaffleFactory.sol:L33` "pre-end empty-raffle refund authority."

- **Factory registry** (L45-L54) grows only through the permissionless `createRaffle` (L105, L123-L125), and

- **Raffle `factory` and `quoteToken`** are `immutable` (L55, L58). The `factory` value is the factory contract,

**How the verdict was reached:**
- **Why not `implemented`.** The test names "sponsor" among the accounts that must have no privileged control,
  and "cancel" among the forbidden powers. `Raffle.sol:L282` gives the sponsor, and only the sponsor, the power
  to end any raffle before `endTime` while it has no entries. The terminal `Refunding` state follows (L299), and
  the prize is returned through `releaseSponsorPrize` (L395-L407).
- **Why `contradicted` rather than `partial`.** This is not enforcement missing from one path. The code
  deliberately exempts the sponsor (`msg.sender != sponsor &&`), and the NatSpec documents it as a
  "cancellation authority". The requirement is a universal negative, and an affirmative grant of the forbidden
  power is incompatible with it. It is also not an edge path: every raffle starts `Active` with zero entries,
  so before the first sale there is no case in which the cancel prohibition holds.
- **What still holds.** Every other clause: owner/role, pause, rescue, parameter setter, forced withdrawal,
  upgrade, deployer and treasury. The contradiction is confined to the cancel clause, on the empty-raffle
  branch of `enableRefunds`.
- **Confidence is high on the code facts.** The verdict turns `implemented` only if "No administrator" is read
  to exclude a sponsor's rights over its own unsold raffle. The supplied test rules that reading out; see the
  first open question.

**Open questions:**
- **The two specification sources disagree.** DESIGN.md says "No administrator" and never mentions a sponsor
  cancellation. The in-code NatSpec grants one explicitly: `IRaffle.sol:L37` "empty-raffle cancellation
  authority"; `IRaffle.sol:L322-L323`; `IRaffle.sol:L410` and `IRaffleFactory.sol:L33` "pre-end empty-raffle
  refund authority". If sponsor cancellation of an unsold raffle is intended, DESIGN.md (and this test) should
  say so. If it is not intended, the defect is the `msg.sender != sponsor &&` exemption at `Raffle.sol:L282`.
- **Cross-reference, outside this record.** The same L282 exemption bears on the DESIGN.md sentence "Refunds
  open at deadline." That belongs to that requirement's record.
- **Not assessed here.** Who administers the external quote token and the Chainlink wrapper. Their code is not
  in scope, and DESIGN.md designates them as "trusted canonical dependencies". The in-scope code makes no claim
  about whether those contracts have owners or mutable settings. `getVrfRequestPrice` (`Raffle.sol:L436-L438`)
  reads the wrapper's live pricing.
