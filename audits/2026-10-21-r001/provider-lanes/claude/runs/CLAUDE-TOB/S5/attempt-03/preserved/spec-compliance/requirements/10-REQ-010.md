## REQ-010 — The quote token must report exactly six decimals; the factory constructor enforces it

> "Decimal precision required from the immutable quote token."
> — packages/contracts/src/libraries/RaffleConstants.sol:L23 (`@notice` on `QUOTE_TOKEN_DECIMALS`)

Holds-if criterion from the task (the task's words, not the NatSpec's): "QUOTE_TOKEN_DECIMALS == 6, and the factory
constructor compares decimals() against it."

Supporting text, verbatim:
- RaffleFactory.sol:L59: "The quote token must report exactly six decimals; the wrapper and quote token must contain
  deployed code."
- IRaffleFactory.sol:L67 and L69: "Raised when the quote token does not use the required six-decimal precision." /
  "Required decimal precision, exactly six."
- IRaffleFactory.sol:L63: "Raised when the quote token cannot report its decimal precision."
- DESIGN.md:L2: "One entry costs 1,000,000 units of canonical six-decimal USDC."

**Verdict:** implemented · confidence: high

---

**What this demands of an implementation:**
1. `RaffleConstants.QUOTE_TOKEN_DECIMALS` is `6`.
2. The `RaffleFactory` constructor calls `decimals()` on `quoteToken_` and reverts unless the result equals that
   constant. Construction must not be able to complete on any path where the comparison did not pass.
3. The token becomes "the immutable quote token" in three places: the factory immutable, the implementation immutable,
   and every clone. Each of them must be fed only by a token that passed the check.

---

**Where enforcement lives:**

```solidity
// RaffleConstants.sol:L23-L24
/// @notice Decimal precision required from the immutable quote token.
uint8 internal constant QUOTE_TOKEN_DECIMALS = 6;
```
- Condition 1 holds: the type is `uint8` and the value is `6`.

```solidity
// RaffleFactory.sol:L65-L78
constructor(address quoteToken_, address vrfWrapper_, address protocolTreasury_) {
    _requireContract(quoteToken_);
    _requireContract(vrfWrapper_);
    if (protocolTreasury_ == address(0)) revert ZeroAddress();

    uint8 quoteDecimals = 0;
    try IERC20Metadata(quoteToken_).decimals() returns (uint8 decimals_) {
        quoteDecimals = decimals_;
    } catch {
        revert UnsupportedQuoteToken(quoteToken_);
    }
    if (quoteDecimals != RaffleConstants.QUOTE_TOKEN_DECIMALS) {
        revert InvalidQuoteTokenDecimals(quoteDecimals, RaffleConstants.QUOTE_TOKEN_DECIMALS);
    }
```
- The call goes through OZ `IERC20Metadata` (imported at L5), declared `function decimals() external view returns
  (uint8);` (IERC20Metadata.sol:L25).
- L76 compares the reported value against the library constant itself, not a copy or a parameter. The test is a strict
  `!=`, so only exactly `6` passes. Condition 2 holds.
- The check is unconditional. L66-L68 can only revert, so no branch before L76 skips it.

```solidity
// RaffleFactory.sol:L85, L89, L91
quoteToken = quoteToken_;
address implementation = address(new Raffle(quoteToken_, vrfWrapper_));
raffleImplementation = implementation;
```
- Both uses that make `quoteToken_` immutable come after L76 in straight-line code.

**Paths walked:**

Every outcome of the constructor's `decimals()` read:
- `quoteToken_` has no code → `_requireContract` (L66 → L184 `if (account.code.length == 0) revert NotContract(account);`).
  `decimals()` is never called. Construction reverts. ✓
- `decimals()` reverts, or exhausts its forwarded gas → `catch` at L73 → `revert UnsupportedQuoteToken(quoteToken_)`
  at L74. Construction reverts. ✓
- `decimals()` returns a `uint8` other than 6 → assigned at L72 → L76 is true → `InvalidQuoteTokenDecimals(actual, 6)` at
  L77. Construction reverts. ✓
- `decimals()` returns 6 → L76 is false → execution continues to L80. This is the only path that completes. ✓
- `decimals()` returns data that does not decode as `uint8`: shorter than 32 bytes, or a word above 255. The constructor
  reverts whether or not that decode failure reaches `catch`, because `catch` also reverts (L74). The remaining
  dependency is that the decoder rejects an out-of-range word instead of masking it to its low byte. `src` has no
  `pragma abicoder v1` (0 hits), so the 0.8.x default ABI coder v2 applies. See Open Questions. ✓
- The `quoteDecimals = 0` initializer at L70 cannot carry through: the only non-reverting branch of the `try` overwrites
  it at L72, and `0 != 6` would revert at L77 regardless.

Where the validated token propagates:
- Factory: `quoteToken` is `immutable` (RaffleFactory.sol:L33). It is assigned only at L85, after L76. ✓
- Implementation: `new Raffle(quoteToken_, vrfWrapper_)` at L89 runs after L76. `Raffle.quoteToken` is `immutable`
  (Raffle.sol:L58) and assigned only at L162 from that argument. ✓
- Clones: `createRaffle` clones `raffleImplementation` (RaffleFactory.sol:L106), the immutable set at L91. ERC-1167 is
  "a minimal bytecode implementation that delegates all calls to a known, fixed address" (Clones.sol:L13-L14), and the
  runtime word at Clones.sol:L56 begins `5af4` (GAS, DELEGATECALL). Each clone therefore runs the implementation's code
  and reads the `quoteToken` immutable embedded in it. `RaffleInitParams` (IRaffle.sol:L45-L54) has no quote-token
  field, and `initialize` (Raffle.sol:L176-L206) writes none, so initialization cannot substitute another token. ✓
- Raffle's quote-token transfers, `safeTransferFrom` (Raffle.sol:L224) and `safeTransfer` (L566), both go through that
  immutable.

Path that does not reach the check:
- `Raffle`'s own constructor (Raffle.sol:L155-L166) rejects only `quoteToken_ == address(0)` (L159). It does not check
  decimals; its NatSpec states the precondition instead ("Canonical six-decimal USDC contract fixed for the
  implementation and every clone.", L153). Within `src`, the only deployment is `new Raffle` at RaffleFactory.sol:L89,
  so on every in-scope path the argument has already passed L76. A `Raffle` deployed directly by a third party skips
  the check. That instance records the third party as `factory` (Raffle.sol:L161), and none of its clones is
  registered by the canonical factory: `isRaffle[...] = true` is written only at RaffleFactory.sol:L125. Such a
  deployment is not "the factory constructor" in the holds-if, so it is not counted against this requirement.

---

**How the verdict was reached:** Both holds-if conditions were checked in the code. The constant is `6`
(RaffleConstants.sol:L24). The factory constructor calls `decimals()` and compares the result with `!=` against that
constant, reverting on mismatch (RaffleFactory.sol:L71-L78). Every other outcome of that call also ends in a revert:
no code (L66), call failure (L74), and undecodable return data. The token is written to an immutable, or passed to the
implementation, only after the comparison (L85, L89). Clones inherit the implementation's immutable and cannot replace
it during initialization.

That makes this `implemented` and not `partial`: no in-scope path completes construction, or yields a factory-created
raffle, without the comparison passing. The one path without the check, a directly deployed `Raffle`, lies outside the
factory constructor the holds-if names.

It is not `stronger-than-spec`. The extra revert when `decimals()` cannot be read (L74) follows from requiring a
precision at all, and it is documented (IRaffleFactory.sol:L63). The NatSpec at RaffleFactory.sol:L59 was not taken as
evidence; the code at L65-L91 was read.

**Open questions:**
- The undecodable-return path depends on ABI coder v2 range-checking a returned `uint8` rather than masking it. If the
  decoder masked, a token returning a 32-byte word whose low byte is `0x06` would pass L76. The pragma is
  `solidity 0.8.36` with no `abicoder` override, so v2 is the default. This was not confirmed by compiling or by a test.
  DESIGN.md:L4: "No tests, audit history, accepted-risk lists or scanner results are provided."
- The check runs once, at construction. `decimals()` is never read again (single call site, RaffleFactory.sol:L71). If
  the quote token is upgradeable and later reports a different precision, nothing in `src` detects it. DESIGN.md:L2
  covers this under trust: "Quote token and Chainlink wrapper are trusted canonical dependencies". The holds-if asks
  only for the construction-time comparison.
- Precision is checked but token identity is not. RaffleFactory.sol:L60-L61: "Deployment tooling must supply and verify
  the target chain's official USDC address because the constructor cannot prove token identity from metadata." This
  is outside this requirement.
