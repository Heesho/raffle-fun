## REQ-38 — No asset moves from one raffle clone to another

> "Never move assets between raffle clones."
> — DESIGN.md line 2, sentence 15

Related NatSpec: `Raffle.sol:L152` "Clones share these immutables but hold isolated storage."; `Raffle.sol:L587`
"Identifies same-factory protocol plumbing that cannot safely own a ticket or receive a payout."

---

**Verdict:** partial · confidence: high

---

**What this demands of an implementation:** The task gives this condition: "No code path in a raffle or the
factory moves USDC, prize NFTs or tickets from one raffle clone to another, or lets one clone's holdings pay another
clone's liabilities; no payout can go to another clone." Concretely, that means three things:

1. Every outbound transfer a clone makes needs a recipient that is not another factory clone. That covers USDC
   through `quoteToken`, the prize through `prizeToken`, and tickets through the clone's own ERC-721 ledger.
2. Every inbound pull needs a source that is not another clone. That covers the USDC `transferFrom` and the
   factory's prize escrow.
3. Each clone pays its liabilities only from its own balance.

The payout recipients are `msg.sender` (refunds, the cash winner, the NFT winner), the stored `sponsorRecipient`
and the stored `protocolTreasury`.

---

**Where enforcement lives:**

```solidity
// Raffle.sol:L593-L605
function _isProtocolDestination(address destination, address prizeToken_)
    private
    view
    returns (bool unsafeDestination)
{
    IRaffleFactory canonicalFactory = IRaffleFactory(factory);
    unsafeDestination = destination == address(this) || destination == factory || destination == address(quoteToken)
        || destination == address(i_vrfV2PlusWrapper) || destination == prizeToken_
        || destination == canonicalFactory.raffleImplementation();
    if (!unsafeDestination && destination.code.length != 0) {
        unsafeDestination = canonicalFactory.isRaffle(destination);
    }
}
```
- This rejects the clone itself (L599) and any clone in the factory registry (L603). The registry is consulted
  **only when the address already has code** (L602).
- Every clone that exists is registered. `createRaffle` deploys the clone (RaffleFactory.sol:L106) and registers it
  (L125) inside one `nonReentrant` call (L97), so a revert anywhere removes the clone too. Between L106 and L125 the
  only external calls are the new clone's `initialize` and its view calls back into the factory (Raffle.sol:L601,
  L603). No untrusted code runs in that window.
- Clones are deployed with `create` (OZ Clones.sol:L57, `instance := create(value, 0x09, 0x37)`). That address
  depends on the factory address and nonce, not on caller input, so anyone can compute it before deployment. Until
  the clone is deployed the address has no code. L602 then skips the registry lookup and the screen returns `false`.

Where the screen runs:

```solidity
// Raffle.sol:L564-L567 — every USDC payout: L342 cash winner, L369 refunds, L380 sponsor, L390 treasury
function _transferQuote(address to, uint256 amount) private {

// Raffle.sol:L497-L502 — every ticket mint and transfer

    previousOwner = super._update(to, ticketId, auth);
}
```

- `isRaffle[...]` is true only for clones that are already registered, so a future clone address passes.
- `_requireContract(params.prizeToken)` (L155, L183-L185) requires the prize contract to have code, and L159
  rejects registered clones. Together they mean one clone's ticket contract can never be another clone's prize.

The payout that is never screened:

```solidity
// Raffle.sol:L395-L407
function releaseSponsorPrize() external override nonReentrant {
    Status currentStatus = status;
    if (currentStatus != Status.CashWon && currentStatus != Status.Refunding) {
        revert SponsorPrizeUnavailable(currentStatus);
    }
    if (prizeClaimed) revert PrizeAlreadyClaimed();

    address recipient = sponsorRecipient;
    prizeClaimed = true;
    prizeToken.transferFrom(address(this), recipient, prizeTokenId);          // L404 — no _isProtocolDestination
    if (prizeToken.ownerOf(prizeTokenId) != recipient) revert PrizeDeliveryVerificationFailed(recipient);
    emit SponsorPrizeReleased(msg.sender, recipient, address(prizeToken), prizeTokenId);

```
- `sponsorRecipient` is assigned once, at L198. The only screens on it ran at creation (RaffleFactory.sol:L163-L169
  and Raffle.sol:L193-L195).
- The USDC payout to the same address is screened again when it is paid (`releaseSponsorProceeds` L380 →
  `_transferQuote` L565). The prize payout is not.
- No caller check: anyone can trigger the release.

Outbound transfers to a clone that is already deployed:
- `releaseSponsorProceeds` L380 → `_transferQuote` L565 → L602-L603: a registered clone as recipient reverts
  `InvalidQuoteDestination`. ✓
- `releaseProtocolFees` L390 → L565. ✓ The treasury also cannot become a clone. A clone deployed at the treasury
  address fails its own `initialize` at L190, because L599 compares `destination == address(this)`.
- `refundTickets` L369 (recipient `msg.sender`) and the cash branch of `redeemWinningTicket` L342 (recipient the
  ticket owner, who is `msg.sender`) → L565. ✓
- NFT branch of `redeemWinningTicket` L334: there is no screen, but the recipient is `msg.sender` (L320-L321), and no
  Raffle code calls `redeemWinningTicket` on another contract (see Searched), so a clone is never the caller. ✓
- `buyEntries` mint L235, and the inherited ERC-721 `transferFrom` / `safeTransferFrom` (OZ ERC721.sol:L115-L136) →
  `_update` L498: a ticket sent to a registered clone reverts. ✓ The ERC-721 receiver hook on a clone
  (`onERC721Received` L416-L431) also refuses everything except the factory's exact prize deposit.
- **`releaseSponsorPrize` L402-L405: the prize NFT goes to `sponsorRecipient` with no screen.** ✗ — this is the gap.
  1. When the raffle is created, the sponsor passes a precomputed future clone address as
     `params.sponsorRecipient`. It passes RaffleFactory.sol:L166, because the address is not registered. It passes
     Raffle.sol:L193, because L602 skips the registry for a code-less address. It is stored at L198.
  2. Anyone calls `createRaffle` until a clone lands at that address. It is registered at RaffleFactory.sol:L125.
  3. The first raffle reaches `CashWon` or `Refunding`. For an empty raffle the sponsor can do this at once through
     `enableRefunds` (L279-L284).
  4. Anyone calls `releaseSponsorPrize`. L404 moves the prize from the first clone into the second. L405 passes
     because the second clone is now the owner.

  `transferFrom` calls no receiver hook (OZ ERC721.sol:L115-L125), so the second clone's `onERC721Received` guard
  never runs. NatSpec L410-L411 says such NFTs "remain outside protocol accounting and cannot be rescued".

Outbound transfers to an address before a clone is deployed there (timing variants of the same L602 gate):
- `releaseSponsorProceeds` L380, called before the future clone exists: L565 passes, and the USDC lands at the
  address the clone later occupies. That USDC sits outside the clone's `accountedQuoteBalance` (L468-L470). ✗
  (depends on timing)
- A ticket minted with `buyEntries(recipient = future clone)` (L235) or transferred there: L498 passes, and the
  receiver hook is skipped for a code-less target (OZ ERC721Utils.sol:L32). Once the clone is deployed it owns
  another clone's ticket and has no code path that could use it. ✗ (depends on timing)

Inbound pulls:
- `buyEntries` L224, `quoteToken.safeTransferFrom(msg.sender, address(this), grossAmount)`: the source is the
  caller. Clones never call `buyEntries` and never grant approvals (0 approve hits), so no one can pull USDC from a
  clone. ✓
- `createRaffle` RaffleFactory.sol:L128, `prize.safeTransferFrom(msg.sender, raffle, params.prizeTokenId)`: the
  source is the sponsor. Raffle never calls `createRaffle` (its only factory calls are views at L601 and L603), and
  clones never approve the factory. A standards-compliant ERC-721 therefore rejects any attempt to take a prize a
  clone holds. ✓

Cross-clone liabilities:
- Every outbound transfer debits `address(this)`. L334 and L404 pass `from = address(this)`, and L566
  `safeTransfer` debits the calling contract. Liabilities live in the clone's own storage (L91-L106, summed at
  L469). No function reads another clone's state, and Raffle never casts an address to `IRaffle`. ✓
- Paths that only write storage and make no transfer: `enableRefunds` L276-L301, `_settleWinningTicket`
  L533-L558, `fulfillRandomWords` L509-L524. ✓
- Native ETH, which is not one of the three named assets: L257 pays the trusted wrapper (Chainlink
  VRFV2PlusWrapperConsumerBase.sol:L76-L89). L267 returns `msg.value - paidPrice` to `msg.sender`. A clone's
  `receive()` reverts (L171-L173). ✓

**How the verdict was reached:**

- **Not `implemented`:** L404 moves a prize NFT out of one clone and into another with no destination check. The
  configuration that leads there passes every creation-time check, because both creation checks reject only clones
  that already exist (RaffleFactory.sol:L166 consults the registry; Raffle.sol:L602 consults it only for addresses
  with code). This breaks the requirement's own wording: "no payout can go to another clone".
- **Not `contradicted`:** the code screens clone destinations on every USDC payout (L565) and on every ticket
  movement (L498) at the moment of transfer. It keeps clone ticket contracts out of the prize slot
  (RaffleFactory.sol:L155, L159). It never draws on another clone's balance, and it never makes one clone the caller
  of another clone's payout functions. The requirement holds on those paths. What fails is one payout path plus
  timing variants, and they all need a precondition the sponsor chooses: a future clone address as
  `sponsorRecipient`, or a ticket sent to a future clone address.
- **Root cause, shared by every ✗ path:** the destination screen treats a code-less address as safe (L602), and
  clone addresses are computable before deployment (Clones.sol:L57). `_transferQuote` and `_update` close the gap
  for clones that are already deployed by screening again at transfer time. `releaseSponsorPrize` does not screen
  again.

**Open questions:**
- Does "payout to another clone" cover an address that becomes a clone only after the payout? That is the timing
  variant for USDC at L380 and for tickets at L498. If it does not, those paths hold and only L404 fails. The verdict
  is `partial` either way.
- ERC-1167 proxies of the implementation deployed by third parties are not counted here as raffle clones. They
  cannot be initialized (L178, `msg.sender != factory`) and are not in `isRaffle`.
- A malicious prize contract controls its own ledger. During the factory's L128 call it could reassign a token that
  another clone escrows. Raffle and factory code never ask it to move a token out of a clone. `IRaffle.sol:L14-L15`
  limits support to "honest, standards-compliant ERC-721s", and DESIGN.md line 2 states "arbitrary prize contracts
  and ticket recipients are untrusted". This is not counted as a raffle or factory code path.
