## REQ-009 — Global entry price is exactly 1,000,000 raw six-decimal units (one USDC)

> "Global entry price: exactly 1,000,000 raw six-decimal quote-token units, or one USDC."
> — packages/contracts/src/libraries/RaffleConstants.sol:L20 (@notice)

Supporting text:
- "Returns the fixed raw six-decimal quote-token price of one entry." / "One entry price, exactly 1,000,000 raw units."
  (IRaffle.sol:L394-L395)
- "Defines one autonomous NFT raffle using fixed-price USDC entries" (IRaffle.sol:L10)
- "One entry costs 1,000,000 units of canonical six-decimal USDC." and "Refund outcome pays 100% per entry and returns
  prize." (DESIGN.md:L2)

The holds-if criterion comes from the task, not from the documents: "ENTRY_PRICE == 1_000_000 is a constant, and every
purchase charge and refund uses it."

**Verdict:** implemented · confidence: high

---

**What this demands of an implementation:**
1. One price value equal to 1,000,000. It must be fixed at compile time, with no storage slot, setter, or per-raffle
   parameter, so it is the same for every raffle ("Global").
2. Every quote-token pull for entries charges `entries × 1,000,000`.
3. Every entry refund pays `entries × 1,000,000`, counting the entries the refunded ticket actually paid for.
4. The "six-decimal" clause (which makes 1,000,000 raw units equal one whole token) needs the quote token to have 6
   decimals.

---

**Where enforcement lives:**

```solidity
// RaffleConstants.sol:L21
uint256 internal constant ENTRY_PRICE = 1_000_000;
// Raffle.sol:L44
uint256 public constant override ENTRY_PRICE = RaffleConstants.ENTRY_PRICE;
```
- Both declarations are `constant`. The value has no storage slot and no writer. `1_000_000` is the Solidity literal
  1000000, and it is the only such literal in `src`.
- No per-raffle price input exists. `CreateRaffleParams` (IRaffleFactory.sol:L20-L26) and `RaffleInitParams`
  (IRaffle.sol:L45-L54) have no price field. Every clone runs the bytecode of the one immutable implementation
  (RaffleFactory.sol:L42, L89-L91, L106), so every raffle uses the same constant.

Purchase charge (the only quote-token inflow in `src`):
```solidity
// Raffle.sol:L223-L224, L233
uint256 grossAmount = uint256(entryCount) * ENTRY_PRICE;
quoteToken.safeTransferFrom(msg.sender, address(this), grossAmount);
...
unsettledPot += grossAmount;
```
- `SafeERC20.safeTransferFrom` (SafeERC20.sol:L43-L47) → `_safeTransferFrom` writes `value` unchanged into the
  `transferFrom` calldata (SafeERC20.sol:L226).
- Overflow: `entryCount` is a `uint128`, and (2^128−1)·10^6 < 2^148, so the product fits in `uint256`. The arithmetic
  is checked anyway, because `src` has no `unchecked`.

Refund (the only entry refund in `src`):
```solidity
// Raffle.sol:L359-L369
address owner = ownerOf(ticketId);
if (msg.sender != owner) revert NotTicketOwner(ticketId, msg.sender, owner);
(uint128 firstEntry, uint128 lastEntry) = ticketRange(ticketId);
aggregateEntries += uint256(lastEntry) - uint256(firstEntry) + 1;
_burn(ticketId);
}
amount = aggregateEntries * ENTRY_PRICE;
remainingRefundLiability -= amount;
_transferQuote(msg.sender, amount);
```
- `_transferQuote` (Raffle.sol:L564-L567) screens the destination and then calls `quoteToken.safeTransfer(to, amount)`.
  `_safeTransfer` writes `value` unchanged into the calldata (SafeERC20.sol:L183).
- The entry count comes from the stored range. That range is written once, at purchase (Raffle.sol:L226-L232), as
  `firstEntry = totalEntries + 1` and `lastEntry = totalEntries + entryCount`, so `lastEntry − firstEntry + 1 = entryCount`.
  Each ticket's refund therefore equals the `grossAmount` charged for it at L223. `_ticketRanges` has one write
  (L232) and one read (L452).

Six-decimal precondition:
```solidity
// RaffleFactory.sol:L70-L78
try IERC20Metadata(quoteToken_).decimals() returns (uint8 decimals_) { quoteDecimals = decimals_; }
catch { revert UnsupportedQuoteToken(quoteToken_); }
if (quoteDecimals != RaffleConstants.QUOTE_TOKEN_DECIMALS) { revert InvalidQuoteTokenDecimals(...); }
```
- `QUOTE_TOKEN_DECIMALS = 6` (RaffleConstants.sol:L24). The implementation is built from the same checked
  `quoteToken_` (RaffleFactory.sol:L89), and `Raffle.quoteToken` is immutable (Raffle.sol:L58, L162).

**Paths walked:**
- `buyEntries` (Raffle.sol:L209-L237). Branches L215-L221 revert before any transfer, so nothing is charged on them.
  The success path charges `entryCount × ENTRY_PRICE` at L223-L224. ✓
- `refundTickets` (Raffle.sol:L349-L372). An ID that was never minted would return range `(0,0)` from `ticketRange`
  (L451-L455), which computes as 1 entry. It cannot get there: `ownerOf` (ERC721.sol:L61-L63) → `_requireOwned`
  (L426-L432) reverts at L359 when the owner is zero. The same revert covers burned IDs, and a duplicate ID in the
  batch, which `_burn` at L364 has already burned by its second occurrence. Every refunded ticket has its
  purchase-time range. Payout is `aggregateEntries × ENTRY_PRICE` at L367. ✓
- `aggregateEntries` overflow. Ranges are disjoint and duplicates revert, so the sum is at most `totalEntries` ≤
  2^128−1, and `× 10^6` fits in `uint256`. ✓
- Refund liability source. `enableRefunds` (L296-L298) copies `unsettledPot`. That value is raised only at L233 (by
  `grossAmount`) and zeroed only at L297 and L553. `Refunding` can be entered only from `Active` or `Drawing`
  (L279-L294), so settlement cannot have zeroed it first. The liability equals the sum of `entryCount × ENTRY_PRICE`,
  and the checked subtraction at L368 uses the same unit. ✓
- Other quote-token outflows (cash winner L342, sponsor L380, protocol L390) are allocations of the pot, not purchase
  charges or refunds. They come from `unsettledPot` (L539) and are outside the holds-if scope. `grossSales` (L474) also
  uses `ENTRY_PRICE`. —
- `requestDraw` native excess return (L262-L270) refunds a VRF fee in native currency, not an entry. Not in scope. —
- `RaffleFactory.createRaffle` (L97-L148) moves only the prize NFT (L128). It charges no quote token and takes no price
  input. ✓

---

**How the verdict was reached:** the price is a single compile-time constant equal to 1,000,000 (RaffleConstants.sol:L21,
Raffle.sol:L44). There is no per-raffle input and no writer. The one purchase-charge path (L223-L224) and the one refund
path (L367-L369) both multiply by it, and the refund's entry count was traced back to the purchase-time range. The
verdict is `implemented` rather than `partial` because the sweeps above found no other quote-token inflow and no other
entry refund. It is not `stronger-than-spec`: the factory's decimals check enforces the requirement's own "six-decimal"
clause and adds no constraint the document lacks.

**Open questions:**
- "or one USDC": the chain verifies only six-decimal metadata, not that the token is USDC. The documents treat token
  identity as a deployment-time trust assumption: "Deployment tooling must supply and verify the target chain's
  official USDC address because the constructor cannot prove token identity from metadata." (RaffleFactory.sol:L60-L61;
  also IRaffleFactory.sol:L7-L9; DESIGN.md:L2 "Quote token and Chainlink wrapper are trusted canonical dependencies").
  This is not a divergence, but the equivalence depends on that assumption.
- The decimals check lives only in the factory constructor. `Raffle`'s own constructor checks only for a nonzero
  address (Raffle.sol:L159). A `Raffle` deployed outside `RaffleFactory` with a token that does not have 6 decimals
  would still charge 1,000,000 raw units, but those would not equal one whole token. Such a deployment is not
  registered in a canonical factory (`isRaffle`, RaffleFactory.sol:L125), and only its deployer could initialize its
  clones (Raffle.sol:L161, L178). It falls outside the factory-created system DESIGN.md describes.
- The charge is the amount requested from `transferFrom`. The contract does not measure its balance before and after,
  so it receives exactly `grossAmount` only under the documented fee-free assumption: "trusted canonical six-decimal
  USDC with standard, non-rebasing, fee-free transfers" (IRaffle.sol:L13-L14).
- The verdict is based on Solidity source. Compiled bytecode was not inspected.
