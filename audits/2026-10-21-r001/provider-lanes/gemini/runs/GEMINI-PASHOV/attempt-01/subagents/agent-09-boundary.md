boundary: `Raffle._isProtocolDestination` call to `canonicalFactory.isRaffle(destination)` gated by `destination.code.length != 0`, combined with `RaffleFactory.createRaffle` deploying clones via `Clones.clone(raffleImplementation)` (`CREATE`).
assumption: The calling code in `Raffle.initialize`, `Raffle._update`, and `RaffleFactory._validateCreateParams` assumes `_isProtocolDestination` and `isRaffle` reject every raffle clone address when `sponsorRecipient` or a ticket recipient is set, so `_transferQuote` will never revert with `InvalidQuoteDestination` and `releaseSponsorPrize` will never send a prize NFT to another raffle clone.
actual: Because `Clones.clone` uses `CREATE` from `address(factory)`, every future raffle clone address is deterministic from `(address(factory), nonce)`. Before that future clone is deployed, `futureClone.code.length == 0` and `isRaffle[futureClone] == false`, so `initialize`, `_validateCreateParams`, `_update`, and `ERC721Utils.checkOnERC721Received` all accept `futureClone`. Once a later `createRaffle` call deploys a clone at `futureClone`, `futureClone.code.length == 45` and `isRaffle[futureClone] == true`.
path: caller computes `futureClone = computeCreateAddress(factory, 1 + raffleCount + 1)` → calls `RaffleFactory.createRaffle` for Raffle 1 with `sponsorRecipient = futureClone` (or calls `Raffle.buyEntries(futureClone, 1)`) → any caller creates Raffle 2 at `futureClone` → `Raffle(raffle1).releaseSponsorProceeds()` reverts with `InvalidQuoteDestination(futureClone)` forever, and `Raffle(raffle1).releaseSponsorPrize()` transfers Raffle 1's prize NFT into Raffle 2 (`futureClone`).
proof:
1. At `raffleCount == 0`, `factory` has nonce 1 (from `new Raffle(...)` in constructor). Raffle 1 will be deployed at nonce 2 (`raffle1`), and Raffle 2 will be deployed at nonce 3 (`raffle2`).
2. Caller calls `createRaffle` for Raffle 1 with `params.sponsorRecipient = raffle2`.
3. In `RaffleFactory._validateCreateParams` (line 799) and `Raffle.initialize` (line 206 -> `_isProtocolDestination` line 615): `raffle2.code.length == 0` and `isRaffle[raffle2] == false`, so initialization of Raffle 1 succeeds with `sponsorRecipient = raffle2`.
4. Similarly, in `Raffle.buyEntries(raffle2, 1)` (line 248): `_update` sees `raffle2.code.length == 0`, and `ERC721Utils.checkOnERC721Received` (line 3112) sees `to.code.length == 0`, so ticket 1 is minted to `raffle2`.
5. Next, `createRaffle` is called to create Raffle 2, which deploys the clone at `raffle2` (`raffle2.code.length == 45`) and sets `isRaffle[raffle2] = true` (line 758).
6. If Raffle 1 resolves to `NftWon` or `CashWon` and settles, calling `Raffle(raffle1).releaseSponsorProceeds()` (line 393) calls `_transferQuote(raffle2, amount)` (line 578), where `_isProtocolDestination(raffle2, address(prizeToken))` now returns `true` and reverts with `InvalidQuoteDestination(raffle2)` forever, stranding `sponsorProceeds`.

description: A caller sets a future clone address as recipient, so later clone creation blocks `releaseSponsorProceeds` or sends the prize to that clone.
fix: Use `Clones.cloneDeterministic` with a salt derived from `msg.sender` and parameters, and check `_isProtocolDestination` in `releaseSponsorPrize` and `redeemWinningTicket`.
