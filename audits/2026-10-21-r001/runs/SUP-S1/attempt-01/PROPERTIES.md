# Independent security properties and reasoning

Notation: E=totalEntries, T=ticketCount, P=1,000,000, U=unsettledPot, R=remainingRefundLiability, W=winnerProceeds, S=sponsorProceeds, F=protocolFees. All properties assume the frozen source and canonical standard quote-token transfers. A mathematical check is not a Solidity proof.

1. **Atomic creation/configuration:** successful create gives one registered clone with sponsor/prize/reserve/end fixed and statusActive. Revert from any initialization, prize receiver, ownerOf or status verification cancels clone creation, mappings, raffleCount and external NFT state changes. Only factory can initialize; implementation is locked. No admin/upgrader/mutable recipient exists.
2. **Partition:** after purchases of positive counts e_i, ticket i holds [1+sum(j<i)e_j,sum(j<=i)e_j]. These ranges are nonempty, contiguous, disjoint and cover [1,E]. Historical ranges never change under ERC721 transfer or burn. There is exactly one historical range for any selected entry.
3. **Numeric bounds:** 0<=T<=E<=2^128-1; P*E<2^148, well below uint256. A permitted purchase keeps E<=max and cannot overflow firstEntry or ticketCount. Refunded sums contain only distinct live ranges and cannot exceed original E. Configured time deltas are calculated in uint256; uint64 truncation of real-world block timestamps is not reachable on practical chains.
4. **Quote conservation:** U+R+W+S+F equals collected USDC less successfully delivered quote claims. Unexpected donations may make actual balance larger; equality to entire token balance is not required. Purchases increase U by P*count; transfer rollback prevents a credit on failed canonical payment. Settlement maps U to W+S+F exactly. Refund activation maps U to R exactly. Releases/refunds reduce one liability and actual canonical balance equally or revert completely.
5. **Splits:** NFT: F=floor(U*500/10000), S=U-F, W=0. Cash: W=floor(U*8000/10000), F=floor(U*500/10000), S=U-W-F. Floors occur once on aggregate pot and sponsor takes all remainder. With integer USDC-entry multiples the specified rates are exact in raw units, so no dust is lost. Refund branch has no sponsor/protocol quote allocation.
6. **Claim exclusivity:** status cannot leave a terminal state. Refund burns cannot be mixed with winner outcome. settlementComplete is set once; prizeClaimed limits NFT release; winnerRedeemed plus burn limits winner claim; clearing S/F/W before transfer prevents repeats. Failed calls revert all local/cross-contract effects within that transaction.
7. **Bearer authority:** current owner, not buyer/sponsor/approved operator, calls redeem/refund. Settlement does not fix a recipient. ERC721 transfers preserve all entry rights. Approval lets an operator transfer the bearer asset in the usual way; that is owner-granted authority.
8. **VRF binding:** wrapper-only raw callback, one accepted request, _requestInFlight gate, exact ID, exactly one random word, drawing state, callback strictly before deadline. Entry=1+(random%E) belongs to [1,E] because requests require E>0. Callback has no loops/token calls/receiver calls. Reserve branch depends only on fixed reserve and frozen final sales count.
9. **Deadline partition:** buying t<end; drawing end<=t<end+2days; sold Active refunds t>=end+2days. After draw at q, callback t<q+2days; Drawing refunds t>=q+2days. Empty sponsor may cancel anytime while Active; anyone may cancel at end. No trusted keeper is required, but transaction funding/inclusion remains necessary.
10. **Rollback:** safeMint receiver rejection restores USDC movement and range assignment. Failed NFT transfer/postcondition or quote transfer restores burn, claim flags and any implicit settlement in the same redemption call. It cannot restore a sponsor payment made in an earlier transaction; that matters under an adversarial prize contract.
11. **Reentrancy boundary:** monetary/lifecycle mutators share one per-clone guard. Unguarded onERC721Received only performs its exact AwaitingPrize activation. Unguarded authenticated VRF path records a result and _requestInFlight blocks request-time callback. Inherited ERC721 mutations require standard ownership/operator authority; none change monetary accounting. Read-only registry/prize owner queries run with static semantics.
12. **Isolation:** each clone has independent storage and token balances. Immutable factory/quote/wrapper addresses are code-embedded and shared without shared mutable pot state. No rescue, aggregate treasury sweep, approval of USDC by raffle, delegatecall target selection or cross-clone balance transfer exists in production entry points.
13. **Liveness:** sold unresolved funds can become refunds at request or callback deadline. Each refund batch is capped100; settlement and callback are O(1) in entries/tickets given ticket ID. A winning range can be discovered off-chain from monotonic historical ranges, e.g. binary search; no on-chain full-ticket loop is required. Independent release functions avoid one recipient blocking another claim. Liveness is not guaranteed against malicious/paused prize delivery, canonical-USDC failure, owner loss or permanently invalid immutable recipients.

The accompanying script checks mathematical economic conservation for E=0..10,000 plus boundary samples through uint128 max; exhaustively partitions E<=9 and tests unique range membership/refund-subset accounting; checks release-order conservation and exact deadline complements; samples uint256 randomness boundary values. It does not validate bytecode, Solidity revert ordering, gas, actual token implementation or deployed oracle authenticity.
