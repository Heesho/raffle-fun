## REQ-10 — Lossless remainder allocation on settlement

> "Reserve met awards NFT and 95% sponsor / 5% treasury. Reserve missed awards 80% gross to winner, 15% sponsor, 5% treasury. Refund outcome pays 100% per entry and returns prize. Rounding is floor on aggregate protocol fee; remainder must be allocated without loss."
> — DESIGN.md # Clean design specification, L2

**Verdict:** implemented · confidence: high

**What this demands of an implementation:** When a resolved raffle settles its unallocated sale pot (`unsettledPot`), the aggregate protocol fee (`protocolFees`) and, on the reserve-missed path (`Status.CashWon`), the cash winner allocation (`winnerProceeds`) are computed using floor rounding, and the sponsor allocation (`sponsorProceeds`) must be computed by subtracting those allocations from `grossPot` (`unsettledPot`) rather than via an independent percentage calculation. After settlement, `winnerProceeds + sponsorProceeds + protocolFees` must equal the entire pre-settlement `unsettledPot` with `unsettledPot` zeroed and zero unallocated remainder on both winning outcome branches (`Status.NftWon` and `Status.CashWon`).

```solidity
// packages/contracts/src/Raffle.sol:L533-L558
    function _settleWinningTicket(uint256 ticketId) private returns (uint256 cashAmount) {
        if (settlementComplete) revert SettlementAlreadyComplete();
        Status result = status;
        if (result != Status.NftWon && result != Status.CashWon) revert InvalidStatus(result);

        _requireWinningTicket(ticketId);
        uint256 grossPot = unsettledPot;
        uint256 protocolFee = Math.mulDiv(grossPot, RaffleConstants.PROTOCOL_FEE_BPS, RaffleConstants.BPS);
        uint256 sponsorAmount;

        if (result == Status.NftWon) {
            sponsorAmount = grossPot - protocolFee;
        } else {
            cashAmount = Math.mulDiv(grossPot, RaffleConstants.CASH_WINNER_BPS, RaffleConstants.BPS);
            sponsorAmount = grossPot - protocolFee - cashAmount;
            winnerProceeds = cashAmount;
        }

        settlementComplete = true;
        winningTicketId = ticketId;
        unsettledPot = 0;
        sponsorProceeds = sponsorAmount;
        protocolFees = protocolFee;

        emit WinningTicketSettled(ticketId, msg.sender, result, cashAmount, protocolFee, sponsorAmount);
    }
```

**How the verdict was reached:**
In `_settleWinningTicket` (`packages/contracts/src/Raffle.sol:L533-L558`), both winning status branches compute `sponsorAmount` by subtracting `protocolFee` (and `cashAmount` when `result == Status.CashWon`) directly from `grossPot = unsettledPot` (`L543` and `L547`) under Solidity 0.8.36 checked arithmetic, and store the resulting allocations in `winnerProceeds`, `sponsorProceeds`, and `protocolFees` while setting `unsettledPot = 0` (`L548, L553-L555`). Every settlement path passes through `_settleWinningTicket` (`L305, L315`), and `settlementComplete` (`L534, L551`) prevents re-settlement. Therefore, `winnerProceeds + sponsorProceeds + protocolFees` always equals the entire pre-settlement `unsettledPot` with zero unallocated remainder, making the verdict `implemented` rather than `partial`.
