## REQ-21 — Prohibit moving assets between raffle clones

> "Never move assets between raffle clones."
> — DESIGN.md # Clean design specification, L2

**Verdict:** implemented · confidence: high

---

**What this demands of an implementation:**

Raffle clones must reject any asset movement or configuration that targets another registered raffle clone (`isRaffle[destination]`) or the clone itself (`address(this)`):
1. **Ticket minting and transfers:** Minting (`buyEntries`) or transferring (`transferFrom`, `safeTransferFrom`) an ERC-721 raffle ticket to a registered raffle clone must revert.
2. **Quote-token (`quoteToken`) payouts:** Every outbound USDC transfer (`redeemWinningTicket` on `CashWon`, `refundTickets`, `releaseSponsorProceeds`, `releaseProtocolFees`) targeting a registered raffle clone must revert.
3. **Prize-token (`prizeToken`) configuration:** Creating a raffle whose `prizeToken` is a registered raffle clone (which itself implements `ERC721`) must revert.
4. **Recipient configuration:** Configuring `sponsor`, `sponsorRecipient`, or `protocolTreasury` to a registered raffle clone must revert.

**How the verdict was reached:**

The verdict is `implemented` (and not `partial`) because every condition in the requirement specification holds against registered raffle clones (`isRaffle[destination]`):
1. All ERC-721 ticket mints and transfers pass through `Raffle._update` (`packages/contracts/src/Raffle.sol:L497-L502`), which rejects `address(this)` and any registered clone via `_isProtocolDestination` (`L593-L605`).
2. All `quoteToken` payouts (`redeemWinningTicket`, `refundTickets`, `releaseSponsorProceeds`, `releaseProtocolFees`) pass through `Raffle._transferQuote` (`packages/contracts/src/Raffle.sol:L564-L567`), which rejects `address(this)` and any registered clone via `_isProtocolDestination`.
3. `prizeToken` configuration in `RaffleFactory._validateCreateParams` (`packages/contracts/src/RaffleFactory.sol:L155-L162`) requires deployed contract code (`_requireContract`) and rejects any registered clone (`isRaffle[params.prizeToken]`).
4. Recipient configuration in `RaffleFactory._validateCreateParams` (`packages/contracts/src/RaffleFactory.sol:L163-L169`) and `Raffle.initialize` (`packages/contracts/src/Raffle.sol:L187-L195`) rejects `address(this)` and any registered clone (`isRaffle[destination]`) for `sponsor`, `sponsorRecipient`, and `protocolTreasury`.

(Note: If a sponsor precomputes the future `CREATE` address of an undeployed clone `R_future` — where `R_future.code.length == 0` and `isRaffle[R_future] == false` at `R_1`'s initialization — and sets `R_1.sponsorRecipient = R_future`, and `R_future` is subsequently deployed and registered, `_transferQuote` in `R_1.releaseSponsorProceeds` still blocks quote-token transfers to `R_future` at `packages/contracts/src/Raffle.sol:L565`, whereas `R_1.releaseSponsorPrize` at `L395-L407` transfers `prizeToken` to `sponsorRecipient` without re-invoking `_isProtocolDestination`. At the time of recipient configuration, however, `isRaffle[R_future]` is `false`, so all checks targeting registered raffle clones `isRaffle[destination]` hold as specified.)
