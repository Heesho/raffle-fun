## REQ-20 — Allocate rounding remainders without loss

> "remainder must be allocated without loss."
> — `target/DESIGN.md:L2`

The complete rounding sentence is:

> "Rounding is floor on aggregate protocol fee; remainder must be allocated without loss."
> — `target/DESIGN.md:L2`

**Verdict:** implemented · confidence: high

---

**What this demands of an implementation:** After rounding monetary allocations from a gross sale pot, the allocated claims must still sum to that entire pot. Residual raw quote-token units must remain assigned to a claim rather than disappear when the pot is cleared. The specified recipient is clarified by the interface:

> "The cash-winner allocation is rounded down; the sponsor receives the remaining raw units."
> — `target/packages/contracts/src/interfaces/IRaffle.sol:L328`

This is a source-only review of the supplied frozen target for requested commit `9238b6ce8eb7f768c0dcd0cfcef26e1427a03155`. No tests, compilation, analyzers, scanners, chain calls, or network research were used.

**Where enforcement lives:**

```solidity
// target/packages/contracts/src/Raffle.sol:L539-L555
uint256 grossPot = unsettledPot;
uint256 protocolFee = Math.mulDiv(grossPot, RaffleConstants.PROTOCOL_FEE_BPS, RaffleConstants.BPS);
uint256 sponsorAmount;

if (result == Status.NftWon) {
    sponsorAmount = grossPot - protocolFee;
} else {
    cashAmount = Math.mulDiv(grossPot, RaffleConstants.CASH_WINNER_BPS, RaffleConstants.BPS);
    sponsorAmount = grossPot - protocolFee - cashAmount;
    winnerProceeds = cashAmount;
}

settlementComplete = true;
winningTicketId = ticketId;
unsettledPot = 0;
sponsorProceeds = sponsorAmount;
protocolFees = protocolFee;
```

- Let `G` be `unsettledPot`, `F = floor(G * 500 / 10000)`, and, in the cash outcome, `W = floor(G * 8000 / 10000)`. These numerators and denominator are constants, not caller-selected values (`libraries/RaffleConstants.sol:L12-L18`; `Raffle.sol:L539-L546`). The three-argument `Math.mulDiv` calls `mul512`; its non-overflow branch returns `low / denominator`, without rounding up (`Math.sol:L37-L46,L206-L216`). Its larger-product branch also subtracts the arithmetic remainder before division (`Math.sol:L218-L275`); it is not reached by the bounded sale amounts described below.
- **NFT outcome:** `S = G - F`, so `F + S = G` exactly. All raw units outside the rounded fee are assigned to the sponsor (`Raffle.sol:L543-L544,L554-L555`).
- **Cash outcome:** `S = G - F - W`, so `F + W + S = G` exactly. Computing the sponsor allocation by subtraction retains the residual from both floor operations; it does not independently round a 15% sponsor allocation (`Raffle.sol:L546-L555`). The fixed rates sum to 8500 of 10000, so their floor allocations cannot exceed `G` (`libraries/RaffleConstants.sol:L12-L18`).
- **Persistence:** the function writes the resulting winner, sponsor, and treasury liabilities as it clears the unsettled pot (`Raffle.sol:L548-L555`). `accountedQuoteBalance` includes all of these liabilities plus refunds and the unsettled pot (`Raffle.sol:L468-L470`). The conservation property follows from the assignments, not from this view function enforcing an invariant.
- **Reachable amount bounds:** purchases reject zero entries and aggregate counts exceeding `uint128`, then collect and credit exactly `entryCount * ENTRY_PRICE` (`Raffle.sol:L218-L235`). With `ENTRY_PRICE = 1_000_000`, `G < 2^148` and even `G * 8000 < 2^161`, so the multiplication feeding `mulDiv` fits 256 bits (`libraries/RaffleConstants.sol:L18-L21`; `Math.sol:L206-L216`). In fact, these fixed-price sale amounts make both percentage divisions exact multiples of raw units. The subtraction formulas nevertheless explicitly preserve any remainder instead of relying solely on this divisibility (`Raffle.sol:L539-L555`).
