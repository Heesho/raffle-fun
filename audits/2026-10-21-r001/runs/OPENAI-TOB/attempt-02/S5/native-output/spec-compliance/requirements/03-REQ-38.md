## REQ-38 — No transfers between raffle clones

> "Never move assets between raffle clones."
> — `target/DESIGN.md:L2`

**Verdict:** partial · confidence: high

**Independent refutation result:** Not refuted. No correction or verdict-category change is required.

This review read the specified prior analysis and independently inspected the frozen target source. The record below is a static source argument, not an executed behavior result. No tests, compilation, analyzers, scanners, fuzzers, chain calls, network research, or other audit records were used.

---

**What this demands of an implementation:** The quoted prohibition applies when an asset moves from one raffle clone to another. A counterexample involving two registered clones of the same factory is sufficient; no interpretation concerning other factories is needed. The relevant question is whether a recipient accepted during initialization can become a clone before delivery, and whether any later check stops delivery.

---

**Where enforcement lives:**

The factory rejects an already registered raffle as a sponsor recipient, along with specified fixed destinations (`target/packages/contracts/src/RaffleFactory.sol:L154-L169`). The clone checks the supplied recipient and then stores it:

```solidity
// target/packages/contracts/src/Raffle.sol:L193-L198
        if (_isProtocolDestination(params.sponsorRecipient, params.prizeToken)) {
            revert UnsafeProtocolDestination(params.sponsorRecipient);
        }

        sponsor = params.sponsor;
        sponsorRecipient = params.sponsorRecipient;
```

The helper excludes the clone itself and fixed protocol addresses, then queries the factory registry only when the destination has code:

```solidity
// target/packages/contracts/src/Raffle.sol:L598-L604
        IRaffleFactory canonicalFactory = IRaffleFactory(factory);
        unsafeDestination = destination == address(this) || destination == factory || destination == address(quoteToken)
            || destination == address(i_vrfV2PlusWrapper) || destination == prizeToken_
            || destination == canonicalFactory.raffleImplementation();
        if (!unsafeDestination && destination.code.length != 0) {
            unsafeDestination = canonicalFactory.isRaffle(destination);
        }
```

Consequently, a nonzero future clone address distinct from those fixed exclusions passes the factory check while unregistered and the initialization check while code-less (`target/packages/contracts/src/RaffleFactory.sol:L154-L169`; `target/packages/contracts/src/Raffle.sol:L181-L198,L598-L604`). The factory uses a public registry mapping and registers each newly initialized clone at creation; it does not reserve earlier recipients against future deployment (`target/packages/contracts/src/RaffleFactory.sol:L54,L97-L148`).

Runtime protection does exist for currently registered same-factory destinations: ticket ownership updates call `_isProtocolDestination` before the inherited update, and quote payouts call it before transferring (`target/packages/contracts/src/Raffle.sol:L497-L502,L564-L567`). Cash-winner redemption, ticket refunds, sponsor proceeds, and protocol fees all call `_transferQuote` (`target/packages/contracts/src/Raffle.sol:L342,L369,L380,L390`). The bundled quote-transfer helper forwards the supplied recipient and checks success (`target/packages/contracts/node_modules/@openzeppelin/contracts/token/ERC20/utils/SafeERC20.sol:L33-L37,L176-L200`).

Sponsor prize release has no corresponding runtime check. Its complete body is:

```solidity
// target/packages/contracts/src/Raffle.sol:L395-L407
    function releaseSponsorPrize() external override nonReentrant {
        Status currentStatus = status;
        if (currentStatus != Status.CashWon && currentStatus != Status.Refunding) {
            revert SponsorPrizeUnavailable(currentStatus);
        }
        if (prizeClaimed) revert PrizeAlreadyClaimed();

        address recipient = sponsorRecipient;
        prizeClaimed = true;
        prizeToken.transferFrom(address(this), recipient, prizeTokenId);
        if (prizeToken.ownerOf(prizeTokenId) != recipient) revert PrizeDeliveryVerificationFailed(recipient);
        emit SponsorPrizeReleased(msg.sender, recipient, address(prizeToken), prizeTokenId);
    }
```

Both allowed statuses reach the same transfer. The postcondition accepts ownership by the stored recipient, without testing whether that address is now registered (`target/packages/contracts/src/Raffle.sol:L395-L405`).

**Paths walked:**

1. **Select the later clone address.** Let `F` be a valid factory and `B` the unused address of a later deployment from it. `createRaffle` calls `Clones.clone(raffleImplementation)` (`target/packages/contracts/src/RaffleFactory.sol:L105-L106`); the selected overload passes zero value and executes `CREATE` (`target/packages/contracts/node_modules/@openzeppelin/contracts/proxy/Clones.sol:L32-L33,L47-L61`). Under that opcode's creator-and-nonce address semantics, a caller can select the address of the next clone after `A`. This is an inference from the deployment instruction, not a computed address or a chain observation. The sequence assumes these creations occur in the selected order, with no intervening factory creation.
2. **Create `A` with `sponsorRecipient = B`.** Use an ordinary sponsor, a distinct permitted treasury, an approved ERC-721 prize, a positive reserve, and an end time within the permitted future window. The concrete parameter restrictions are in `target/packages/contracts/src/RaffleFactory.sol:L97-L104,L154-L184`; the window maximum is 30 days (`target/packages/contracts/src/libraries/RaffleConstants.sol:L29-L30`). The recipient is an ordinary address field, not a type that requires deployed code (`target/packages/contracts/src/interfaces/IRaffleFactory.sol:L20-L25`). Since `B` is still unused and outside the fixed exclusions, both recipient checks pass and `A` stores `B` (`target/packages/contracts/src/Raffle.sol:L176-L205,L593-L605`).
3. **Complete initial escrow.** The factory registers `A`, deposits its prize with `safeTransferFrom`, and verifies both ownership and active status (`target/packages/contracts/src/RaffleFactory.sol:L123-L134`). The receiving hook accepts the exact configured prize from the configured sponsor with the factory as operator, then sets `Active` (`target/packages/contracts/src/Raffle.sol:L416-L430`). Factory approval is a satisfiable prerequisite: the bundled ERC-721 permits owner-granted approval and authorizes an approved operator (`target/packages/contracts/node_modules/@openzeppelin/contracts/token/ERC721/ERC721.sol:L93-L106,L164-L187,L383-L417`).
4. **Create and register `B`.** Create the subsequent clone with its own valid configuration and separate prize. Creation initializes and registers the new clone, but does not inspect or rewrite recipients in earlier clones (`target/packages/contracts/src/RaffleFactory.sol:L97-L148,L154-L179`). The earlier assignment to `A.sponsorRecipient` persists; initialization is one-time and the source has only that one assignment (`target/packages/contracts/src/Raffle.sol:L176-L198`). Both `A` and `B` are now registered (`target/packages/contracts/src/RaffleFactory.sol:L123-L125`).
5. **Open refunds for empty `A`.** Make no entry purchases in `A`. Its sponsor calls `enableRefunds`; in the active, zero-entry branch, only a non-sponsor is rejected before the end time. The function sets `Refunding` (`target/packages/contracts/src/Raffle.sol:L276-L300`). This branch needs neither randomness nor winning-ticket settlement, and does not deliver the prize (`target/packages/contracts/src/Raffle.sol:L276-L301`).
6. **Deliver the prize from `A` to `B`.** Call `A.releaseSponsorPrize()`. With its prize still unclaimed, it calls `prizeToken.transferFrom(A, B, prizeTokenId)` and accepts `ownerOf(prizeTokenId) == B` (`target/packages/contracts/src/Raffle.sol:L395-L405`). Under the bundled ERC-721 behavior, `A`, as owner, is authorized; transfer changes the owner to `B` without consulting `B` (`target/packages/contracts/node_modules/@openzeppelin/contracts/token/ERC721/ERC721.sol:L115-L125,L164-L187,L216-L244`). The owner getter returns that updated ownership (`target/packages/contracts/node_modules/@openzeppelin/contracts/token/ERC721/ERC721.sol:L61-L63,L146-L148,L426-L432`). This is the prohibited asset movement between two existing same-factory clones.

**Attempted refutations and why they do not close the path:**

- **Constructor or initialization invariant:** The implementation locks its own initialization and fixes factory and quote-token addresses (`target/packages/contracts/src/Raffle.sol:L155-L165`), while clone initialization restricts its caller to the factory and runs only once (`target/packages/contracts/src/Raffle.sol:L176-L205`). The factory deploys the implementation and uses it as the clone target (`target/packages/contracts/src/RaffleFactory.sol:L89-L91,L106`). None of those checks requires the recipient to remain free of code or prohibits deploying a later clone at a stored recipient (`target/packages/contracts/src/RaffleFactory.sol:L97-L148,L154-L179`; `target/packages/contracts/src/Raffle.sol:L176-L205`).
- **Reentrancy modifier:** `releaseSponsorPrize` is an external entrypoint whose sole modifier is `nonReentrant` (`target/packages/contracts/src/Raffle.sol:L395`). That modifier checks whether its storage flag equals `ENTERED`, sets it while executing, and resets it afterward; it checks no recipient or registry (`target/packages/contracts/node_modules/@openzeppelin/contracts/utils/ReentrancyGuard.sol:L50-L51,L69-L73,L88-L118`; `target/packages/contracts/node_modules/@openzeppelin/contracts/utils/StorageSlot.sol:L93-L97`). Separate sequential calls satisfy this guard, including a fresh clone's initially zero flag, because only `ENTERED == 2` is rejected at those lines.
- **Receiving clone's NFT hook:** `B.onERC721Received` would reject an unrelated second deposit (`target/packages/contracts/src/Raffle.sol:L416-L430`). It is not called by the sponsor release's plain `transferFrom` (`target/packages/contracts/src/Raffle.sol:L404`; `target/packages/contracts/node_modules/@openzeppelin/contracts/token/ERC721/ERC721.sol:L115-L135`). The receiver callback is an additional step in `safeTransferFrom`, implemented by `ERC721Utils.checkOnERC721Received` (`target/packages/contracts/node_modules/@openzeppelin/contracts/token/ERC721/utils/ERC721Utils.sol:L25-L49`).
- **Inherited ERC-721 destination enforcement:** `Raffle._update` protects transfers of the raffle's own ticket collection (`target/packages/contracts/src/Raffle.sol:L497-L502`; `target/packages/contracts/node_modules/@openzeppelin/contracts/token/ERC721/ERC721.sol:L115-L121,L259-L289`). Sponsor prize release instead calls the separately configured `prizeToken`, so the raffle's ticket override does not execute for that prize's ownership update (`target/packages/contracts/src/Raffle.sol:L200,L404`).
- **Token trust or special behavior:** The interface states, "Supported prizes are honest, standards-compliant ERC-721s." (`target/packages/contracts/src/interfaces/IRaffle.sol:L14-L15`). The sequence uses the supplied ordinary ERC-721 transfer semantics, not a fabricated owner report or malicious callback (`target/packages/contracts/node_modules/@openzeppelin/contracts/token/ERC721/ERC721.sol:L61-L63,L115-L135,L216-L244,L426-L432`). The main specification says, "Quote token and Chainlink wrapper are trusted canonical dependencies; arbitrary prize contracts and ticket recipients are untrusted." (`target/DESIGN.md:L2`). The empty-raffle refund and sponsor release path invokes neither a quote transfer nor a randomness request (`target/packages/contracts/src/Raffle.sol:L276-L301,L395-L407`).
- **Other caller or wrapper:** There is no required wrapper around the external sponsor-release entrypoint (`target/packages/contracts/src/Raffle.sol:L395-L407`). The inherited VRF base's external callback checks wrapper identity and dispatches `fulfillRandomWords`; it does not wrap sponsor release (`target/packages/contracts/node_modules/@chainlink/contracts/src/v0.8/vrf/dev/VRFV2PlusWrapperConsumerBase.sol:L101-L107`). Thus caller-side validation cannot be mandatory for every invocation of the prize-release function.

**How the verdict was reached:** The claimed divergence survives independent inspection. Factory and initialization checks reject existing sibling recipients; ticket transfers and quote payouts also check the current destination (`target/packages/contracts/src/RaffleFactory.sol:L154-L169`; `target/packages/contracts/src/Raffle.sol:L193-L198,L497-L502,L564-L567`). Sponsor NFT release relies on the earlier recipient check and transfers after that address can have become another registered clone (`target/packages/contracts/src/RaffleFactory.sol:L105-L125`; `target/packages/contracts/src/Raffle.sol:L395-L405`). That combination supports `partial`: concrete enforcement on some paths, a reachable uncovered path on another. It does not support `implemented` or `absent`, and changing the verdict to `contradicted` would lose the relevant distinction between checked and unchecked paths. The original description needs no substantive correction.
