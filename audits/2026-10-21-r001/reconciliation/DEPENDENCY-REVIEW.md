## DEP-01 — Next image-optimizer DNS pinning gap: local unit behavior observed

The frozen web package pins Next16.2.12. `apps/web/next.config.ts:9–14` permits all HTTPS hostnames and local HTTP hostnames, but that alone does not establish SSRF. The actual installed Next image defaults set `dangerouslyAllowLocalIP=false`, `dangerouslyAllowSVG=false` and `maximumRedirects=3`. Locked `next/dist/server/image-optimizer.js:895–950` resolves DNS, rejects private IPs, then invokes an ordinary fetch without binding its socket lookup to the checked addresses. Redirects are manual and recursively repeat the private-IP check, so a simple redirect to a stable private address is not assumed to bypass it.

The maintainer advisory requires an attacker-controlled allowed remote host/DNS. Its linked fix pins DNS when fetching external images. The code and local fixture are consistent with that specific preflight/socket DNS mismatch, not a claim that every local URL is allowed. [Maintainer advisory](https://github.com/vercel/next.js/security/advisories/GHSA-cjq9-62q9-8jv4), [DNS-pinning fix](https://github.com/vercel/next.js/commit/e002ad6).

A local-only unit fixture invoked the actual locked `fetchExternalImage` function with the local-IP guard false. Mocked preflight DNS returned public8.8.8.8; the actual fetch socket DNS returned127.0.0.1; a harmless loopback HTTP mock received the request and returned19bytes. No packet was intentionally sent to8.8.8.8 or a production target. This shows the internal function can connect to an address different from the one checked. `dependency-fixture-evidence/attempt-02` contains the command, output and integrity evidence. Attempt01 deliberately remains recorded as unsuccessful: documentation-reserved203.0.113.10 was classified nonpublic and blocked before fetch; its source and output are preserved.

The full `/_next/image` route, URL-parameter validation, initial allowed HTTPS request/TLS, real DNS cache timing, platform routing and deployed reachability were not tested. Direct invocation used HTTP and bypassed route-level remotePatterns checks, so it is not a complete production SSRF demonstration. A real attack would need a route reaching this function and a DNS/redirect/TLS sequence consistent with the deployment. Keep those requirements unresolved.

The frozen NFT image source is attacker-influenced metadata: `src/lib/nft-metadata.ts:17–40,69–73` accepts HTTPS and local HTTP image URLs, rejects credentials and `.svg` suffixes. However, `PrizeArt` and the creation preview explicitly set `unoptimized`, so those rendered NFT images go to the browser rather than automatically entering server image optimization. That mitigates the observed UI flow; it does not by itself prove the framework optimizer endpoint is unavailable to direct requests. The static brand image does use Next Image. This item is a frontend/server dependency exposure, separate from a Raffle/Factory Solidity defect.

Targeted follow-up: reproduce only against an isolated full Next route with controlled DNS/TLS/HTTP redirect fixtures, verify deployed optimizer availability/hosting separately, restrict remote host policy where compatible, then evaluate an explicitly reviewed Next update at least covering the recorded16.3.8 advisory fixes. No update was performed.

## DEP-02 — Next/Sharp image-decoder family: conditional runtime risk

Next16.2.12 and optional Sharp0.35.3 are in the web runtime dependency path. The Next AVIF critical advisory and Sharp libheif high advisory overlap native image decoding. Upstream describes conditional RCE for untrusted AVIF/libheif input; Sharp fixes are reported at0.35.4. A distinct librsvg high advisory is fixed atSharp0.35.5 and has native runtime/platform conditions. These are not automatically three independent RCEs. [Next AVIF advisory](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4), [Sharp libheif advisory](https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c), [Sharp librsvg advisory](https://github.com/lovell/sharp/security/advisories/GHSA-wq5f-xc86-pv6w).

No malicious native image payload was executed. Production OS, libc, installed optional binary, Node hardening and actual image-decoder behavior were not verified. Current unoptimized NFT image components reduce application-flow exposure; default dangerouslyAllowSVG=false also limits the SVG optimizer path. Default WebP output selection alone should not be mistaken for exclusion of AVIF input decoding. The lock explicitly overrides Sharp to0.35.3, so changing only a parent package may preserve the vulnerable native wrapper version. Future remediation needs both the parent package and overrides reviewed, followed by deterministic build and image-flow testing.

## DEP-06 — Registry signature failure is not demonstrated tampering

The signature command reports1286 verified registry signatures and one invalid-signature entry, but its actual error is not a failed cryptographic comparison. The npm `era-contracts` packument is unpublished and lacks the expected versions object. Frozen lock lines5006–5014 resolve this dependency from Matter Labs GitHub codeload at commit `446d391d34bdb48255d5f8fef8a8248925fc98b9`; the Chainlink snapshot aliases `@zksync/contracts` to it. Registry signature verification is therefore querying npm name metadata for a Git-sourced tarball rather than establishing a signature for that Git source. Do not repeat the generic tool suggestion of tampering as an observed fact. [npm registry-signature scope](https://docs.npmjs.com/about-registry-signatures/).

This remains a provenance coverage gap: the lock block pins the commit but has no registry integrity/signature field, and the commit identifier is not itself a publisher signature. The tarball's source authenticity/content was not independently attested. It is also absent from the actual production compiler source closure. Future re-audit should verify the intended upstream commit and content digest/provenance, preserve exact resolution evidence and distinguish Git verification from registry signatures. No dependency replacement or acceptance decision was made.
